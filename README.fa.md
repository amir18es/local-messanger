# مسنجر تیمی (Node.js + Socket.IO + PostgreSQL)

مسنجر راست‌چین فارسی با حساب‌های کاربری مدیریت‌شده توسط ادمین، گروه‌ها، پیام زنده، ویرایش/حذف پیام، عکس پروفایل و ارسال فایل.

> **محدودیت امنیتی:** هیچ نرم‌افزاری را نمی‌توان ۱۰۰٪ غیرقابل نفوذ تضمین کرد. این پروژه چند لایه دفاعی متداول دارد، اما پیش از استفاده سازمانی/حساس باید بازبینی امنیتی مستقل، نسخه پشتیبان و سیاست نگهداری داده داشته باشد. پیام‌ها رمزگذاری سرتاسری (End-to-End Encryption) ندارند؛ مدیر سرور/دیتابیس از نظر فنی می‌تواند به محتوای ذخیره‌شده دسترسی داشته باشد.

## امکانات

- ورود با نام کاربری/رمز عبور؛ ثبت‌نام عمومی غیرفعال است.
- ساخت کاربر، ویرایش نام/نام کاربری/نقش/وضعیت فعال، و تنظیم رمز جدید توسط ادمین.
- ساخت و ویرایش گروه و انتخاب اعضای گروه توسط ادمین.
- پیام زنده با Socket.IO و ذخیره پیام در PostgreSQL.
- ویرایش و حذف نرم‌افزاری پیام توسط نویسنده یا مدیر؛ پیام حذف‌شده در سابقه با نشان حذف باقی می‌ماند.
- ارسال عکس، GIF و فایل‌های مجاز (مثل PDF، ZIP، فایل متنی و بعضی قالب‌های صوتی/ویدیویی). فایل‌ها در پوشه‌ای خارج از وب‌روت قرار دارند و دریافت آن‌ها نیازمند ورود و عضویت در گروه است.
- عکس پروفایل JPG، PNG یا WebP؛ ایموجی و استیکرهای آماده.
- محدودیت حجم فایل، محدودسازی تلاش ورود، هش رمز با bcrypt، نشست ذخیره‌شده در PostgreSQL، کوکی HttpOnly/SameSite و بررسی Origin.

## نیازمندی‌ها

- Node.js نسخه 24 LTS (نسخه 22 یا جدیدتر نیز قابل استفاده است)
- PostgreSQL نسخه 14 یا جدیدتر
- VS Code (یا ویرایشگر دلخواه)

## اجرای محلی در VS Code و Windows

### ۱. ساخت دیتابیس PostgreSQL

PostgreSQL را نصب و اجرا کن. در pgAdmin یک دیتابیس با نام `local_messenger` بساز. نام کاربری و رمز PostgreSQL را نگه دار؛ برای مثال اگر کاربر `postgres` است، رشته اتصال شبیه این می‌شود:

```text
postgresql://postgres:YOUR_PASSWORD@localhost:5432/local_messenger
```

اگر رمز PostgreSQL شامل نویسه‌هایی مثل `@`, `:` یا `/` است، در URL باید URL-encode شود. می‌توانی به‌جای این کار یک کاربر دیتابیس با رمز مناسب ایجاد کنی.

### ۲. باز کردن پروژه

1. فایل ZIP را استخراج کن.
2. در VS Code گزینه **File > Open Folder** را بزن و پوشه `local-messenger-secure` را باز کن.
3. از منوی **Terminal > New Terminal** ترمینال را باز کن.
4. فایل `.env.example` را در همان پوشه کپی کن و نام کپی را `.env` بگذار.

### ۳. تنظیم فایل `.env`

مقادیر نمونه را با اطلاعات واقعی تغییر بده:

```env
DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@localhost:5432/local_messenger
SESSION_SECRET=PASTE_A_LONG_RANDOM_SECRET_HERE
ADMIN_USERNAME=admin
ADMIN_PASSWORD=CHANGE_TO_A_UNIQUE_PASSWORD_12_CHARS_OR_LONGER
ADMIN_DISPLAY_NAME=مدیر سیستم
APP_ORIGIN=
NODE_ENV=development
PORT=3000
UPLOAD_DIR=./uploads
MAX_FILE_MB=15
```

برای ساخت `SESSION_SECRET` در ترمینال VS Code این دستور را اجرا کن و خروجی را در `.env` قرار بده:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

رمز مدیر باید حداقل ۱۲ نویسه باشد. رمز دیتابیس، `SESSION_SECRET` و `.env` را در GitHub قرار نده. فایل `.env` در `.gitignore` است. اگر نام کاربری مدیر از قبل در دیتابیس وجود داشته باشد، اجرای دوباره سرور رمز آن کاربر را بازنویسی نمی‌کند؛ برای تغییر رمز از پنل مدیریت استفاده کن.

### ۴. نصب و اجرا

در ترمینال، از ریشه پروژه:

```bash
npm install
npm run dev
```

در صورت موفقیت، مرورگر را در این آدرس باز کن:

```text
http://localhost:3000
```

با اطلاعات `ADMIN_USERNAME` و `ADMIN_PASSWORD` که در `.env` گذاشته‌ای وارد شو. اولین اجرا، جداول موردنیاز را به‌صورت خودکار ایجاد می‌کند و اگر حساب مدیر وجود نداشته باشد، آن را می‌سازد. گروه «عمومی» نیز ساخته می‌شود.

برای اجرای عادی (بدون حالت watch):

```bash
npm start
```

برای بررسی نحو JavaScript:

```bash
npm run check
```

### ۵. ایجاد کاربران و گروه‌ها

1. وارد مسنجر شو.
2. روی **مدیریت** کلیک کن.
3. در تب «کاربران» یک نام کاربری، نام نمایشی و رمز قوی تعیین کن. کاربران ثبت‌نام عمومی ندارند.
4. در تب «گروه‌ها» گروه ایجاد کن و اعضا را انتخاب کن.
5. کاربران را از صفحه ورود، با نام کاربری و رمزهایی که به آن‌ها داده‌ای وارد کن.

کاربر باید عضو یک گروه باشد تا پیام‌ها و فایل‌های آن گروه را ببیند. هنگام غیرفعال‌کردن کاربر یا تغییر رمز او، نشست‌های ذخیره‌شده او لغو می‌شوند.

## تست در شبکه داخلی

برای دسترسی کاربران شبکه داخلی، سرور و کاربران باید به شبکه‌ای مشترک وصل باشند. سرور را با `npm start` اجرا کن و IP محلی کامپیوتر سرور را با `ipconfig` پیدا کن. کاربران از آدرس زیر وارد شوند:

```text
http://IP-LOCAL-SERVER:3000
```

در صورت نیاز برای پورت TCP `3000` فقط در پروفایل **Private** فایروال Windows قانون ورودی تعریف کن. سرور محلی را مستقیم روی اینترنت عمومی باز نکن؛ برای دسترسی اینترنتی از میزبانی HTTPS، متغیرهای محیطی قوی و تنظیمات امنیتی میزبان استفاده کن.

## انتشار آنلاین روی Render

این پروژه فایل `render.yaml` دارد و به‌عنوان نقطه شروع می‌توان آن را با **Blueprint** از مخزن GitHub ساخت.

1. پروژه را در مخزن GitHub قرار بده (به‌جز `.env` و محتویات پوشه `uploads`).
2. در Render، گزینه **New + > Blueprint** را انتخاب و مخزن را متصل کن.
3. برای `ADMIN_USERNAME` و `ADMIN_PASSWORD` مقادیر امن وارد کن. پس از معلوم‌شدن URL نهایی سرویس، `APP_ORIGIN` را برابر مبدأ کامل آن قرار بده؛ مانند `https://your-service.onrender.com` و بدون `/` انتهایی.
4. پس از پایان دیپلوی، از مسیر `/healthz` می‌توان سلامت اتصال دیتابیس را بررسی کرد.

### نکته بسیار مهم درباره ماندگاری در Render

فایل `render.yaml` برای **آزمایش اولیه** از پلن‌های رایگان استفاده می‌کند. طبق محدودیت‌های Render، دیتابیس رایگان PostgreSQL پس از ۳۰ روز منقضی می‌شود و فایل‌های روی فایل‌سیستم سرویس رایگان هنگام restart/redeploy یا خوابیدن سرویس از بین می‌روند. بنابراین این تنظیم برای نگهداری واقعی پیام‌ها و فایل‌ها مناسب نیست. برای استفاده دائمی:

- دیتابیس PostgreSQL را به پلن پولی با پشتیبان‌گیری ارتقا بده.
- برای فایل‌ها و عکس‌های پروفایل یکی از این دو راه را انتخاب کن: سرویس وب پولی Render به‌همراه Persistent Disk (مثلاً مسیر `/var/data/uploads` و مقدار `UPLOAD_DIR=/var/data/uploads`)، یا فضای ذخیره‌سازی شیءمحور خصوصی S3-compatible. فایل‌ها باید از مسیرهای احراز هویت‌شده برنامه ارائه شوند، نه از پوشه عمومی وب.
- از دیتابیس و فایل‌ها پشتیبان منظم و آزمایش بازیابی داشته باش.

محدودیت‌های رسمی: [Render Free instances](https://render.com/docs/free)، [Persistent Disks](https://render.com/docs/disks)، [Blueprint specification](https://render.com/docs/blueprint-spec).

## یادداشت‌های امنیتی و عملیاتی

- تمام درخواست‌های تغییردهنده از مرورگر با بررسی Origin محافظت می‌شوند؛ اتصال Socket.IO نیز Origin و نشست کاربر را بررسی می‌کند.
- کوکی نشست HttpOnly و SameSite=Strict است؛ در production ویژگی Secure فعال می‌شود. HTTPS باید توسط سرویس میزبان ارائه شود.
- رمزها به‌صورت هش bcrypt ذخیره می‌شوند و هرگز به API برگردانده نمی‌شوند.
- SQLها از پارامترهای bind شده استفاده می‌کنند. فایل‌ها در پوشه عمومی قرار ندارند و فقط اعضای همان گروه می‌توانند دانلود کنند.
- ارسال فایل‌های اجرایی و SVG غیرفعال است. حداکثر حجم را با `MAX_FILE_MB` تعیین کن.
- از رمز یکسان برای دیتابیس، مدیر و سایر سرویس‌ها استفاده نکن؛ `SESSION_SECRET` را در اختیار دیگران قرار نده.
- این پیاده‌سازی رمزگذاری سرتاسری، احراز هویت دومرحله‌ای، آنتی‌ویروس فایل، یا ممیزی امنیتی مستقل ندارد. برای اطلاعات بسیار حساس، این‌ها را پیش از بهره‌برداری سازمانی به طراحی اضافه کن.
