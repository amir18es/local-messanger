# مسنجر تیمی با ذخیره‌سازی فایل (Node.js + Socket.IO)

این نسخه برای اجرا روی Render یا در VS Code بازنویسی شده و به PostgreSQL یا هیچ دیتابیس دیگری وابستگی ندارد. حساب‌ها، گروه‌ها، پیام‌ها و نشست‌های ورود در فایل‌های JSON ذخیره می‌شوند و فایل‌های ارسالی در پوشه `uploads` قرار می‌گیرند.

> **محدودیت مهم Render:** ذخیره فایل به‌تنهایی به معنی ماندگاری روی Render نیست. فایل‌سیستم سرویس‌های Render به‌طور پیش‌فرض موقت است. برای نگه‌داشتن پیام‌ها و فایل‌ها پس از restart/redeploy باید Persistent Disk داشته باشی؛ این دیسک به سرویس وب پولی نیاز دارد. فایل `render.yaml` این دیسک را روی `/var/data` تنظیم می‌کند. منابع: [Persistent Disks](https://render.com/docs/disks) و [Free instances](https://render.com/docs/free).

## امکانات

- ورود با نام کاربری و رمز عبور؛ ثبت‌نام عمومی غیرفعال است.
- ایجاد کاربران، ویرایش اطلاعات، تعیین نقش مدیر یا کاربر، تغییر رمز و غیرفعال‌کردن حساب توسط مدیر.
- ایجاد گروه و مدیریت اعضا توسط مدیر.
- پیام زنده از طریق Socket.IO؛ پیام‌ها در `messenger.json` ذخیره می‌شوند.
- ویرایش و حذف نرم پیام‌ها توسط نویسنده یا مدیر.
- عکس پروفایل، GIF و تصویر، فایل‌های PDF/ZIP/متنی و برخی فرمت‌های صوتی/ویدیویی.
- ایموجی و استیکرهای آماده در رابط کاربری.
- نشست‌های ورود در فایل `sessions.json`، هش رمز با bcrypt، محدودیت درخواست، محدودیت تلاش ورود، بررسی Origin و هدرهای امنیتی.

## محل فایل‌های داده

به‌صورت پیش‌فرض، برنامه داده‌ها را در این ساختار می‌نویسد:

```text
data/
├── messenger.json   # کاربران، گروه‌ها و پیام‌ها
├── sessions.json    # نشست‌های ورود
└── uploads/         # فایل‌ها و تصاویر ارسالی و عکس‌های پروفایل
```

`messenger.json` با نوشتن اتمی به‌روزرسانی می‌شود تا احتمال ناقص‌شدن فایل هنگام نوشتن کاهش یابد. این روش برای مسنجر کوچک و یک نمونه از Node.js مناسب است؛ برای داده بسیار حجیم، چند نمونه سرور هم‌زمان یا استفاده پرترافیک، فایل JSON جایگزین مناسبی برای دیتابیس واقعی نیست. از فایل‌ها نسخه پشتیبان منظم بگیر و بازیابی نسخه پشتیبان را آزمایش کن.

## نیازمندی‌ها

- Node.js نسخه 24 LTS (یا نسخه 22.16 به بعد)
- VS Code یا ویرایشگر دیگر

**PostgreSQL لازم نیست نصب باشد.**

## اجرا در VS Code روی ویندوز

1. ZIP را استخراج کن و پوشه `local-messenger-file-storage` را در VS Code باز کن.
2. از منوی `Terminal > New Terminal` ترمینال را باز کن.
3. فایل `.env.example` را کپی کن و نام کپی را `.env` بگذار.
4. مقادیر `SESSION_SECRET`، `ADMIN_USERNAME` و `ADMIN_PASSWORD` را مقداردهی کن.

برای تولید کلید تصادفی نشست، این دستور را در ترمینال اجرا کن و خروجی را به‌عنوان `SESSION_SECRET` قرار بده:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

نمونه تنظیمات محلی:

```env
DATA_DIR=./data
UPLOAD_DIR=./data/uploads
SESSION_SECRET=PASTE_GENERATED_RANDOM_SECRET_HERE
ADMIN_USERNAME=admin
ADMIN_PASSWORD=CHANGE_TO_A_UNIQUE_PASSWORD_12_CHARS_OR_LONGER
ADMIN_DISPLAY_NAME=مدیر سیستم
NODE_ENV=development
PORT=3000
MAX_FILE_MB=15
APP_ORIGIN=
```

رمز مدیر باید حداقل ۱۲ نویسه باشد. `SESSION_SECRET` باید حداقل ۳۲ نویسه تصادفی داشته باشد. فایل `.env` را به GitHub نفرست.

5. این دستورات را اجرا کن:

```bash
npm install
npm run check
npm run dev
```

6. در مرورگر وارد `http://localhost:3000` شو و با اطلاعات مدیر وارد شو.

در اولین اجرا، برنامه پوشه داده و فایل‌های JSON را ایجاد می‌کند و حساب مدیر و گروه «عمومی» را می‌سازد. اگر فایل `data/messenger.json` از قبل وجود داشته باشد، حساب مدیر موجود بازنویسی نمی‌شود؛ برای تغییر رمز از پنل مدیریت اقدام کن.

برای اجرای عادی بدون حالت watch:

```bash
npm start
```

## انتشار روی Render بدون PostgreSQL

این پروژه `render.yaml` دارد و از Blueprint استفاده می‌کند. در نسخه فعلی فایل تنظیمات، دیسک پایدار روی `/var/data` متصل می‌شود و مسیرهای داده این‌ها هستند:

- `DATA_DIR=/var/data`
- `UPLOAD_DIR=/var/data/uploads`

### مراحل

1. محتویات پوشه پروژه را در ریشه یک مخزن GitHub قرار بده؛ `.env` یا پوشه `data` شامل داده‌های خصوصی را منتشر نکن.
2. در Render از `New + > Blueprint` مخزن را متصل کن.
3. هنگام درخواست مقادیر دستی، `ADMIN_USERNAME` را تعیین کن و یک رمز قوی برای `ADMIN_PASSWORD` وارد کن. `SESSION_SECRET` توسط Blueprint تولید می‌شود.
4. چون Persistent Disk فقط روی سرویس وب پولی قابل استفاده است، سرویس با پلن دارای دیسک تنظیم شده. پیش از نهایی‌کردن، قیمت و منطقه را در Render بررسی کن.
5. پس از دیپلوی موفق، آدرس HTTPSای را که Render نشان می‌دهد باز کن.

اگر سرویس موجودی را بدون Blueprint ساخته‌ای، می‌توانی از Dashboard در بخش Environment متغیرهای `DATA_DIR=/var/data` و `UPLOAD_DIR=/var/data/uploads` را اضافه کنی و از بخش Disk یک Persistent Disk با Mount Path برابر `/var/data` ایجاد کنی. اگر مسیر فایل‌ها خارج از Mount Path باشد، ماندگار نخواهند بود.

### نکته درباره رایگان‌بودن

در پلن رایگان Render نمی‌توان Persistent Disk متصل کرد و فایل‌های محلی در restart، sleep یا redeploy از بین می‌روند. بنابراین ذخیره‌سازی JSON با ماندگاری واقعی روی Render رایگان سازگار نیست. این نسخه عمداً برای ماندگاری فایل‌ها، دیسک پایدار را در `render.yaml` تعریف می‌کند. اگر استفاده رایگان ضروری است، باید یک فضای ذخیره‌سازی پایدار خارجی انتخاب شود؛ این پروژه در حال حاضر آن سرویس خارجی را پیاده‌سازی نکرده است.

## متغیرهای محیطی

| متغیر | توضیح |
|---|---|
| `DATA_DIR` | پوشه فایل اصلی JSON و نشست‌ها؛ روی Render باید داخل دیسک پایدار باشد. |
| `UPLOAD_DIR` | پوشه فایل‌ها و تصاویر ارسالی؛ روی Render باید داخل دیسک پایدار باشد. |
| `SESSION_SECRET` | کلید محرمانه نشست‌ها؛ حداقل ۳۲ نویسه تصادفی. |
| `ADMIN_USERNAME` | نام کاربری مدیر اولیه. |
| `ADMIN_PASSWORD` | رمز مدیر اولیه؛ حداقل ۱۲ نویسه. |
| `ADMIN_DISPLAY_NAME` | نام نمایشی مدیر. |
| `NODE_ENV` | برای Render برابر `production` و برای توسعه برابر `development`. |
| `PORT` | پورت HTTP؛ Render این مقدار را خودکار تعیین می‌کند. |
| `MAX_FILE_MB` | حداکثر حجم فایل به مگابایت. |
| `APP_ORIGIN` | اختیاری؛ مبدأ کامل سایت با HTTPS و بدون اسلش انتهایی، برای مثال `https://your-service.onrender.com`. اگر خالی باشد از Host درخواست استفاده می‌شود. |

## نسخه پشتیبان

برای پشتیبان‌گیری باید از هر سه مورد نسخه بگیری:

- `messenger.json`
- `sessions.json` (اختیاری؛ در صورت حذف کاربران باید دوباره وارد شوند)
- تمام پوشه `uploads`

بهترین کار این است که در زمان توقف کوتاه برنامه از فایل‌ها کپی بگیری تا فایل JSON و فایل‌های آپلود هم‌زمان باشند. نسخه پشتیبان را در GitHub عمومی قرار نده.

## امنیت و محدودیت‌ها

هیچ برنامه‌ای را نمی‌توان ۱۰۰ درصد غیرقابل نفوذ تضمین کرد. در این پروژه از bcrypt، کوکی HttpOnly/SameSite، HTTPS در Render، بررسی Origin، محدودسازی تلاش ورود، محدودیت حجم و نوع فایل و کنترل دسترسی گروه استفاده شده است؛ اما رمزگذاری سرتاسری (End-to-End Encryption)، احراز هویت دومرحله‌ای و ممیزی امنیتی مستقل وجود ندارد.

این پیاده‌سازی برای **یک نمونه Node.js** طراحی شده است؛ فایل JSON و نشست فایل‌محور برای چند نمونه هم‌زمان مناسب نیست. برای استفاده بزرگ یا سازمانی، دیتابیس و سامانه ذخیره‌سازی اختصاصی قابل‌اعتمادتر است.
